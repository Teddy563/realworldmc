# RealWorldMC cleanup audit — 2026-10-10

Scope: current 1.21.1 implementation, 26.2 companion, local map/photo services, release packaging and saved-world compatibility. This was a Ponytail full audit with fixes, followed by correctness and compatibility checks.

## Findings and changes

1. **[delete] Unused low-resolution photo endpoint.** Removed `/native/face` and its unused six-face download method. The in-game renderer uses the high-resolution panorama endpoint. This removes a second photo download path; panorama metadata and provider error handling remain tested.
2. **[delete] Unused dependency.** Removed `@gltf-transform/functions` from the service manifest and lockfile. No source imported it. Four direct runtime dependencies remain; no new dependency was added.
3. **[native] Current code identity.** Moved Java sources to `dev.realworldmc`, renamed entrypoints, mixin configurations, Gradle projects and logging to RealWorldMC, and changed the OSM request user agent. Active releases contain the current implementation only. Old source paths and outdated root artifacts are archived during local synchronization.
4. **[shrink] Configuration migration.** Use one current settings file, `config/realworldmc.json`. Import an existing legacy file unchanged only when the new file is absent. New environment variable names take priority over legacy aliases. Preserve unknown JSON fields during migration. Malformed or null settings no longer overwrite the user's file or return a null configuration.

The unused endpoint removes ten method lines plus its route; the dependency removal reduces direct dependencies by one. The full change adds requested camera controls, a fade, migration handling and regression checks, so a total line reduction is not claimed.

## Requested behavior

- New worlds default to the Palace of Parliament, Bucharest: **44.427454, 26.087287**. Existing saves retain their own geographic origins. `/earth goto 44.427454, 26.087287` visits the palace in an existing Earth world.
- Flight credits include RealWorldMC after the provider credits. Flight and Street View credits ease to roughly 38% opacity while chat is open and return to full opacity when it closes. Chat settings are unchanged.
- 1.21.1 keeps vanilla F5 and adds server-owned `/earth camera 1`, `/earth camera 2`, `/earth camera 3` for active Street View only. The earlier custom X binding and client command registration were removed. A pending Street View walk acknowledgement no longer pins an already-detached camera inside the player.

## Compatibility intentionally retained

Saved registry namespaces, dimension identifiers, region data keys, the legacy Fabric alias and old configuration/environment import names remain. Removing these without a world migration would break existing saves and integrations. They do not load a second copy of the old implementation. The project uses Apache 2.0. Third-party dependency notices and provider attribution remain separate.

## Validation

- Minecraft 1.21.1 production build and client check remapping pass.
- Eight server GameTests pass, including old settings migration, palace defaults, damaged settings preservation and saved geographic codec round-trip.
- Nineteen geographic/navigation/walking/fade checks pass.
- Twenty-four service tests pass, including current-versus-legacy environment precedence.
- Minecraft 26.2 production build passes; its new GUI screen accessor is used for the credit fade.
- Isolated production OpenGL fixture passes with the installed Iris/Sodium and Camera Utils, Camera Overhaul and FreeLook versions: first/rear/front camera selection and separation, photo pixels, hidden collision colour, textured excavations and TNT, large-coordinate scale, clipping and render-state restoration.

The running profile's F5 binding was checked both on disk and in memory. It was assigned to Toggle Perspective, with no conflicting F5 binding; Camera Utils was not hiding the player or detaching the camera. The cause of the reported physical F5 key being ignored was not reproduced. Street View camera commands provide alternate access there; the fixture does not simulate the user's physical keyboard or prove full-profile gameplay.

Native photo gameplay and alternate camera controls remain 1.21.1 features. The 26.2 build remains an experimental companion. Full-profile live photo alignment, shader transitions and long flights still need manual verification; no public release was published by this audit.
